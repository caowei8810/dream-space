## 计划与实际偏差审计

2026-08-07 完成首次执行审计。功能主线与产品目标一致，但商用保障计划落后于功能实现：阶段 D 原先只有四条粗粒度验收条件，无法覆盖安全、治理、可观测性、灾备和生产发布的独立门禁；部署文档也仍停留在原型静态站点。

本计划已据此将阶段 D 拆成 D1-D6，并将真实供应商阻塞、额度账务模型、多实例对账风险、上线阻断项和关键架构决策纳入 [商用就绪审计与决策记录](commercial-readiness.md)。原计划没有日期和负责人基线，因此不使用主观百分比判断延期；后续以可复核的准入/退出证据评估进度。

## 阶段 B：用户端 MVP

### 目标

跑通以下最小闭环：

```text
灵感列表 -> 灵感详情 -> 登录 -> 创建会话 -> 提交任务
-> Worker 模拟生成 -> SSE 返回进度 -> 展示结果 -> 下载
```

管理端同期只实现登录、灵感管理和任务查询。模型结果先使用可重复的模拟数据，避免真实供应商接入阻塞业务开发。

### C5：阶段 C 生产级可靠性验收

- C5a（供应商无关）：至少两个 Worker 并发运行，对账使用可超时租约或等价机制；演练领取实例崩溃、租约接管、重复投递、Redis 重启、对象写入失败和数据库短暂不可用，最终任务、额度流水和对象引用收敛一致。

| D5 生产发布 | 正式拓扑、环境隔离、迁移、灰度、回滚、密钥轮换和灾难手册 | 未开始 | 预发布发布及回滚演练通过             |
| D6 上线验收 | 负载、容量、成本、供应商限额、安全和跨团队上线评审       | 未开始 | P0 风险清零并批准生产放量            |

### D1 验收条件

- API 具备按身份、IP 和高成本动作分层限流，登录、验证码、上传和生成不能被绕过。
- 安全响应头、HTTPS、可信代理、CORS 白名单、Cookie 和 CSRF 策略有代码及代理层双重验证。
- 生产 Secret 使用密钥管理服务，完成最小权限、轮换和泄漏应急演练。
- SAST、依赖、镜像或主机漏洞扫描以及上传攻击面测试进入 CI/发布门禁。

### D2 验收条件

- 登录、权限、额度调整、内容发布、审核处置和系统配置等高风险操作写入不可抵赖审计日志。
- 管理端支持审核申诉、人工复核和双人审批需要的状态与证据链。
- 明确数据分类、留存期限、账户删除、数据导出和隐私请求处理流程。
- 灵感素材、字体、提示词、用户上传和生成结果具备授权、投诉及下架流程。

### D3 验收条件

- Web、Admin、API 和 Worker 使用关联请求 ID 的结构化日志，敏感数据完成脱敏。
- API 延迟/错误、队列积压、任务成功率、供应商错误、对象存储和额度差异具备指标与看板。
- 核心链路具备跨 API、队列、Worker 和供应商的追踪，告警包含可执行处置手册。
- 通过故障注入验证告警到达、定位和升级路径，记录恢复时间。

### D4 验收条件

- PostgreSQL 执行自动备份与时间点恢复，对象存储开启版本或等价保护；Redis 不作为唯一业务事实来源。
- 在隔离环境恢复数据库与对象，校验任务、额度流水和对象引用一致性。
- RPO/RTO 经业务批准并通过演练；备份加密、保留、访问和删除满足数据策略。

### D5 验收条件

- 开发、CI、预发布和生产环境隔离，生产使用托管 PostgreSQL、Redis 和对象存储。
- 发布采用不可变构建产物、迁移前置检查、健康/就绪探针、灰度放量和自动停止条件。
- 数据库变更遵循 expand-contract；应用回滚、前向修复和密钥轮换均完成演练。
- 多实例 Worker 和对账任务完成租约、崩溃接管、重复投递和网络分区演练。

### D6 验收条件

- 预发布环境完成真实供应商全链路、峰值负载、限额、降级和成本预算测试。
- 内部 SLO、容量阈值、供应商依赖目标和首批放量规模有测量依据并获批准。
- [商用就绪审计](commercial-readiness.md) 中 P0 风险全部关闭，P1 风险有负责人和期限。
- 产品、运营、研发、安全和合规完成上线清单评审，回滚负责人和沟通路径明确。

套餐、权益、订单、支付结果和退款属于商用后台范围，但必须建立在不可变额度流水、幂等支付回调、套餐权益快照和审计之上，按 ADM-2A/ADM-6 分步交付。发票、优惠券、复杂营销和分销暂不进入当前阶段；引入时单独补充税务、营销风控和合规评审。

## 评估规则

- 每个阶段结束时逐项更新验收条件，不用主观百分比代替证据。
- 存在阻断性未完成项时，阶段不得标记为“已完成”。
- 非阻断问题必须记录负责人、处理阶段和风险，不得静默带入下一阶段。
- 每次评估记录对应分支、提交、检查命令和结果，便于复核与回滚。
