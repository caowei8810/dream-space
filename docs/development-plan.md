## 阶段 B：用户端 MVP

### 目标

跑通以下最小闭环：

```text
灵感列表 -> 灵感详情 -> 登录 -> 创建会话 -> 提交任务
-> Worker 模拟生成 -> SSE 返回进度 -> 展示结果 -> 下载
```

管理端同期只实现登录、灵感管理和任务查询。模型结果先使用可重复的模拟数据，避免真实供应商接入阻塞业务开发。

## 阶段 C：真实生成能力

### 目标

接入对象存储、上传、真实模型供应商、生成前后审核、图片处理、额度冻结/结算、失败重试、死信队列和定时对账。

### 验收条件

- 供应商适配器可替换，业务层不依赖具体 SDK。
- 任务状态迁移、回调验签、幂等、取消和重试测试通过。
- 输入与输出审核、文件清洗、签名下载和数据归属检查通过。
- 供应商故障、Worker 重启和对账补偿演练通过。

## 阶段 D：运营与上线

### 目标

完善用户与额度、审核申诉、模型路由、系统配置、审计日志、监控告警、备份恢复、部署和合规能力。

### 验收条件

- 管理后台 RBAC 和高风险操作审计检查通过。
- 关键指标、日志、追踪和告警可用于定位生产问题。
- 备份恢复、部署回滚、安全扫描和上线清单通过。
- 运营、研发、安全和合规负责人完成上线评审。

## 评估规则

- 每个阶段结束时逐项更新验收条件，不用主观百分比代替证据。
- 存在阻断性未完成项时，阶段不得标记为“已完成”。
- 非阻断问题必须记录负责人、处理阶段和风险，不得静默带入下一阶段。
- 每次评估记录对应分支、提交、检查命令和结果，便于复核与回滚。
