# 管理端产品需求

本文档是阶段 1 普通用户需求之外的管理端正式需求基线，结合造梦空间当前的灵感、生成会话、任务、图片资产、额度和审核模型制定。它描述“要解决什么问题”；页面结构和接口边界见 [管理端功能架构](admin-console-architecture.md)。

## 1. 范围与非目标

### 本期范围

- 管理员独立登录、会话安全、角色权限和管理员账号。
- 工作台运营概览、用户/任务/灵感/图片资产管理。
- 提示词、参考图、生成结果的自动审核、人工复核、下架和申诉。
- 模型、供应商、路由、参数能力、成本和故障降级管理。
- 系统配置、操作审计、数据隐私请求、告警入口和低优先级额度对账。

### 暂不纳入

- 普通用户端视觉改版或社区社交功能。
- 支付、会员、充值、订单、退款和发票。
- 在线画布、视频生成和复杂资产编辑器。
- 直接在管理端调用第三方 SDK 或直接连接数据库。

## 2. 使用角色

| 角色             | 任务               | 数据范围                 | 主要写权限                             |
| ---------------- | ------------------ | ------------------------ | -------------------------------------- |
| Owner            | 负责平台和安全     | 全部                     | 账号、角色、模型发布、系统配置、审计   |
| Admin            | 负责日常运营       | 全部业务数据             | 内容、用户协助、任务处置、审核规则草稿 |
| Content Operator | 管理灵感和公开资产 | 内容与关联任务           | 创建、编辑、排序、发布、下架           |
| Moderator        | 处理风险内容与申诉 | 审核队列和关联资产       | 审核决定、下架、申诉结论               |
| Model Operator   | 维护模型服务       | 模型、供应商、路由、成本 | 草稿和健康检查，不可自审发布           |
| Support          | 协助用户           | 最小必要用户数据         | 添加客服备注、发起受控协助             |
| Viewer           | 查看运营状态       | 脱敏只读数据             | 无                                     |

权限必须按资源和动作拆分，不能只依赖一个粗粒度角色字符串。涉及额度调整、解封、模型发布、规则变更、隐私导出和删除的操作必须二次确认并写审计。

## 3. 功能需求

### ADM-001 工作台

- 展示任务接受量、成功率、失败率、平均耗时、待审核量、供应商健康和队列积压。
- 指标支持时间范围、模型和环境筛选，并链接到对应列表。
- 只突出需要操作的异常；正常额度对账不占用主视觉，有 `BLOCKED` 项时才展示入口。
- 所有指标注明统计窗口和数据更新时间，禁止把前端本地计算当作运营真相。

### ADM-002 基础业务管理

- 用户：搜索、状态、注册时间、生成统计、额度、风险标记、会话、审核记录和隐私请求。
- 灵感：草稿、元数据、来源授权、分类、排序、发布、下架、恢复和批量操作。
- 资产：参考图、原图、缩略图、对象归属、审核状态、校验和、生命周期和访问权限。
- 任务：按用户、会话、模型、状态、审核状态和时间筛选，查看参数快照、事件、错误、重试、死信和结果。
- 每个列表支持服务端分页、排序白名单、空态、错误重试和导出权限控制。

### ADM-003 权限与安全管理

- 管理员账号支持邀请/停用、角色分配、会话撤销、最近登录和安全事件。
- 角色支持权限查看、临时授权、有效期和审批人；不能由操作者给自己升级权限。
- API 对匿名、普通用户、低权限管理员和越权管理员分别返回 401/403。
- 高风险动作必须携带原因、二次确认和请求 ID；审计记录不可由普通管理员删除。

### ADM-004 图片与内容审核

- 自动审核保存规则版本、供应商/引擎、决策、风险码、置信度和原始响应摘要。
- 自动通过、自动拒绝和可疑三种结果均可配置后续动作；生产默认不因审核服务异常而静默放行。
- 人工队列支持领取、转派、批量处理、证据查看、备注和决策历史，防止并发覆盖。
- 处理结果包括通过、拒绝、下架、恢复、升级和需要补充资料；拒绝/下架必须有对用户可解释的原因。
- 申诉支持提交、初审、复审、最终结论和通知；复审人员不能是原决定人。
- 违规生成任务需正确处理结果可见性、下载权限和额度结算，不得只修改页面状态。

### ADM-005 模型与供应商管理

- 模型目录保存展示名、供应商模型 ID、版本、能力、比例、分辨率、张数上限和状态。
- 供应商保存凭据引用、健康状态、超时、限流、回调验签配置和最近错误，Secret 不回传前端。
- 路由支持默认模型、按人群灰度、故障降级、熔断和回滚；发布前显示影响范围。
- 参数模板把用户端选项映射到供应商字段，校验兼容性并版本化。
- 成本和额度规则保存生效时间、单位成本、倍率和审批链，历史任务使用不可变快照。
- 模型配置生命周期为草稿、校验、待审批、已发布、已回滚，禁止直接改线上值。

### ADM-006 系统运营与配套能力

- 系统配置统一管理外围模拟开关、上传限制、并发、审核策略、维护模式和功能开关。
- 审计日志按操作者、资源、动作、时间、请求 ID 和结果查询，敏感值脱敏。
- 告警入口链接到指标、日志和处置手册；管理端不复制另一套监控真相。
- 隐私请求支持数据导出、删除、匿名化、留存期限和关联任务影响评估。
- 额度对账保留为 P2 运维功能，仅对差异、补偿和人工阻塞项提供详情和处置入口。

## 4. 数据与状态要求

管理端展示的所有业务状态必须来自 API。状态变更必须具有操作者、时间、原因和前后值；需要异步处理的动作返回任务 ID 或事件流。

审核状态至少区分 `PENDING`、`AUTO_APPROVED`、`AUTO_REJECTED`、`REVIEW_REQUIRED`、`MANUAL_APPROVED`、`MANUAL_REJECTED`、`APPEALED` 和 `CLOSED`。生成任务的技术状态与内容审核状态分开，不能用“任务成功”推断“内容可公开”。

模型发布、权限变更、额度调整和资产下架必须幂等；重复请求不能创建第二条发布记录、第二次结算或第二次通知。

## 5. 验收门禁

- 桌面 1280px、窄桌面 902px 和移动 390px 无导航覆盖、横向溢出或不可操作按钮。
- 每个写操作至少有 API 单测、权限测试、错误/加载/空状态和一条真实浏览器路径。
- Viewer、Support、Moderator、Model Operator 和 Owner 的越权路径均返回正确的 401/403。
- 人工审核从领取到决定、申诉到复审、下架到恢复均能在数据库和审计中还原。
- 模型草稿发布、健康检查、路由灰度、回滚和供应商失败均有可重复 smoke。
- 用户任务、审核、结果、下载、额度和通知状态在管理端与用户端一致。
- 不提交真实手机号、图片、供应商密钥、审核原文或生产数据。

## 6. 实施顺序

1. `ADM-0` 管理端壳、权限上下文、通用列表/详情和错误状态。
2. `ADM-1` 工作台、用户、任务、灵感和图片资产基础管理。
3. `ADM-2` 管理员账号、角色权限、临时授权和审计日志。
4. `ADM-3` 自动/人工审核队列、下架恢复和申诉。
5. `ADM-4` 模型、供应商、路由、参数和成本管理。
6. `ADM-5` 系统配置、隐私请求、指标告警和上线治理。
7. `ADM-6` 额度对账与备份恢复运营增强，作为低交互优先级但高安全要求的后台能力。

每个切片完成后先自测，再通知验收，验收通过后才能提交 PR；未完成项不得在阶段计划中标记为完成。
