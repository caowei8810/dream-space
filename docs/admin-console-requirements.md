# 管理端产品需求

本文档是阶段 1 普通用户需求之外的管理端正式需求基线，结合造梦空间当前的灵感、生成会话、任务、图片资产、额度和审核模型制定。它描述“要解决什么问题”；页面结构和接口边界见 [管理端功能架构](admin-console-architecture.md)。

## 1. 范围与非目标

### 本期范围

- 管理员独立登录、会话安全、角色权限和管理员账号。
- 工作台运营概览、用户/任务/灵感/图片资产管理。
- 用户余额、额度流水、套餐权益、订单和退款查询及受控处置。
- 计费管理：标准单价、活动折扣、计费规则版本、实时余额扣款和套餐额度消费。
- 提示词、参考图、生成结果的自动审核、人工复核、下架和申诉。
- 模型、供应商、路由、参数能力、成本和故障降级管理。
- 提示词风控规则、系统配置、定时任务、数据生命周期、操作审计、数据隐私请求、告警入口和低优先级额度对账。

### 暂不纳入

- 普通用户端视觉改版或社区社交功能。
- 发票、优惠券、复杂营销活动和多级分销；基础套餐、订单、支付结果及退款是商用必备范围。
- 在线画布、视频生成和复杂资产编辑器。
- 直接在管理端调用第三方 SDK 或直接连接数据库。

## 2. 使用角色

| 角色             | 任务               | 数据范围                 | 主要写权限                             |
| ---------------- | ------------------ | ------------------------ | -------------------------------------- |
| Owner            | 负责平台和安全     | 全部                     | 账号、角色、模型发布、系统配置、审计   |
| Admin            | 负责日常运营       | 全部业务数据             | 内容、用户协助、任务处置、审核规则草稿 |
| Content Operator | 管理灵感和公开资产 | 用户生成内容与关联任务   | 挑选、补充展示信息、排序、发布、下架   |
| Moderator        | 处理风险内容与申诉 | 审核队列和关联资产       | 审核决定、下架、申诉结论               |
| Model Operator   | 维护模型服务       | 模型、供应商、路由、成本 | 草稿和健康检查，不可自审发布           |
| Support          | 协助用户           | 最小必要用户数据         | 添加客服备注、发起受控协助             |
| Viewer           | 查看运营状态       | 脱敏只读数据             | 无                                     |

权限必须按资源和动作拆分，不能只依赖一个粗粒度角色字符串。涉及额度调整、解封、模型发布、规则变更、隐私导出和删除的操作必须二次确认并写审计。

## 3. 功能需求

### ADM-001 工作台

- 展示任务接受量、成功率、失败率、平均耗时、待审核量、供应商健康和队列积压。
- 指标支持时间范围、模型和环境筛选，并链接到对应列表。
- 只突出需要操作的异常；正常额度对账不占用主视觉，有 `BLOCKED` 项时才展示入口。
- 所有指标注明统计窗口和数据更新时间，禁止把前端本地计算当作运营真相。

### ADM-002 基础业务管理（业务运营）

- 用户：搜索、状态、注册时间、生成统计、额度、风险标记、会话、审核记录和隐私请求。
- 灵感精选：只能从用户已生成且审核通过的图片中挑选，补充标题、分类、排序和展示说明后发布；支持下架、恢复和批量操作，禁止后台新建不存在用户生成来源的灵感。
- 资产：参考图、原图、缩略图、对象归属、审核状态、校验和、生命周期和访问权限。
- 任务：按用户、会话、模型、状态、审核状态和时间筛选，查看参数快照、事件、错误、重试、死信和结果。
- 每个列表支持服务端分页、排序白名单、空态、错误重试和导出权限控制。

灵感发布必须保留原始用户、任务、提示词摘要、模型和审核记录的关联；后台发布动作只改变公开展示状态和精选元数据，不复制或伪造图片来源。

### ADM-002A 用户余额、套餐与订单

- 用户详情展示可用额度、冻结额度、累计获得/消耗、当前套餐、权益有效期和最近流水；所有金额与额度使用整数最小单位。
- 额度赠送、扣减、冻结、释放、消费、退款和过期必须写不可变流水，使用幂等键，余额由事务和流水约束维护；后台禁止直接编辑余额字段。
- 套餐支持草稿、上架、下架和版本化，配置价格、额度、有效期、并发、模型、分辨率和生成数量权益；历史订单保留购买时的套餐快照。
- 订单支持按用户、订单号、渠道、状态和时间查询，记录支付回调、退款和对账引用；重复回调/退款不得重复入账。
- 额度调整、套餐赠送和退款要求独立权限、原因、请求 ID 和审计；高金额或批量操作进入双人审批。

### ADM-002B 计费管理

- 平台标准批价默认为 `0.10 元/张`，以分为最小货币单位保存，禁止使用浮点数参与结算。
- 计费规则支持模型、分辨率、生成数量和生效时间维度；每次任务必须保存计费规则版本和单张最终价格快照。
- 活动规则支持在标准价基础上配置折扣，例如 `50%`（五折）；支持活动编码、适用用户/套餐/模型范围、开始/结束时间、叠加策略和启停。
- 同一张图片只能命中一条最终计费规则；活动规则优先级、不可叠加和冲突处理由服务端确定，不能由前端计算。
- 规则发布采用草稿、校验、审批、发布、回滚生命周期；已产生的任务继续使用原规则快照，不受后续改价影响。
- 不订购套餐的用户按最终单价从实时余额扣款；余额不足时整次请求拒绝，不允许生成部分图片后再补扣。
- 套餐购买由计费引擎生成订单、支付结果和套餐权益快照；例如 `10 元 / 500 张`，支付成功后增加 500 张可用额度。
- 套餐额度消费按张扣减，优先使用即将到期的权益；额度扣减、冻结、释放、消费、退款和过期必须写不可变流水。
- 套餐余额与现金余额分账管理，不能把 500 张套餐额度直接换算成现金余额，也不能用页面统计反推账务结果。
- 任务提交时先按图片数量原子预扣资源；任务失败、取消、审核拒绝或入队失败时释放/返还，成功后结算为消费。
- 同一请求使用幂等键；重复提交不能重复扣款、重复消耗套餐额度或重复创建订单。
- 并发请求通过数据库事务、行级锁或等价原子条件更新保证余额和套餐额度不透支；扣款失败的请求不能进入 Worker。
- 退款、人工补偿和管理员调整都必须关联原订单/原流水，填写原因，保留前后余额和审批记录。

### ADM-003 基础管理与权限管理（管理系统基础能力）

- 管理员账号以唯一工号（`employeeNo`）为主标识，支持姓名、登录标识、状态、所属角色、邀请/激活/停用/撤销和最近登录信息。
- 角色为可配置实体，支持名称、编码、说明、状态和高风险标记；不得仅使用固定角色枚举代替角色管理。
- 权限点为资源-动作（`resource:action`）实体，角色与权限点、管理员账号与角色均使用显式关联关系。
- 支持账号详情、角色分配、权限矩阵、会话撤销和安全事件查询；所有变更必须由 API 校验并写入审计。
- 禁止操作者给自己增加高风险权限；禁止停用或移除系统最后一个 Owner；高风险变更需要原因、二次确认和请求 ID。
- 按权限过滤导航或按钮只是前端辅助行为，不能替代本模块的账号、角色、权限数据与服务端授权。

- 管理员账号支持邀请/停用、角色分配、会话撤销、最近登录和安全事件。
- 角色支持权限查看、临时授权、有效期和审批人；不能由操作者给自己升级权限。
- API 对匿名、普通用户、低权限管理员和越权管理员分别返回 401/403。
- 高风险动作必须携带原因、二次确认和请求 ID；审计记录不可由普通管理员删除。

### ADM-004 图片与内容审核

- 自动审核保存规则版本、供应商/引擎、决策、风险码、置信度和原始响应摘要。
- 自动通过、自动拒绝和可疑三种结果均可配置后续动作；生产默认不因审核服务异常而静默放行。
- 人工队列支持领取、转派、批量处理、证据查看、备注和决策历史，防止并发覆盖。
- 处理结果包括通过、拒绝、下架、恢复、升级和需要补充资料；拒绝/下架必须有对用户可解释的原因。
- 申诉支持提交、初审、复审、最终结论和通知；复审人员不能是原决定人。
- 违规生成任务需正确处理结果可见性、下载权限和额度结算，不得只修改页面状态。

### ADM-005 模型与供应商管理

- 模型目录保存展示名、供应商模型 ID、版本、能力、比例、分辨率、张数上限和状态。
- 供应商保存凭据引用、健康状态、超时、限流、回调验签配置和最近错误，Secret 不回传前端。
- 路由支持默认模型、按人群灰度、故障降级、熔断和回滚；发布前显示影响范围。
- 参数模板把用户端选项映射到供应商字段，校验兼容性并版本化。
- 成本和额度规则保存生效时间、单位成本、倍率和审批链，历史任务使用不可变快照。
- 模型配置生命周期为草稿、校验、待审批、已发布、已回滚，禁止直接改线上值。

### ADM-006 系统运营与配套能力

- 系统配置统一管理外围模拟开关、上传限制、并发、审核策略、维护模式和功能开关。
- 审计日志按操作者、资源、动作、时间、请求 ID 和结果查询，敏感值脱敏。
- 告警入口链接到指标、日志和处置手册；管理端不复制另一套监控真相。
- 隐私请求支持数据导出、删除、匿名化、留存期限和关联任务影响评估。
- 额度对账保留为 P2 运维功能，仅对差异、补偿和人工阻塞项提供详情和处置入口。

### ADM-007 风控配置与定时任务

- 风控配置覆盖提示词黑白名单、词组/正则、分类器阈值、用户/设备/IP 频控、重复生成、图片审核阈值和人工抽检比例。
- 规则按适用对象、优先级、动作、有效期和灰度范围版本化，支持测试样例、命中预览、审批发布和一键回滚；不得直接编辑线上生效规则。
- 每次命中保存规则版本、风险类别、动作和关联用户/任务，敏感原文按权限脱敏和按期清理。
- 定时任务管理展示任务编码、Cron、启停、上次/下次运行、耗时、成功/失败数量、错误摘要和运行日志，支持受控立即执行及重跑。
- 清理任务按数据类型分别配置保留期，至少覆盖失败/取消任务、生成图片、参考图、临时对象、会话事件和过期验证码；必须使用分布式租约、分批处理、幂等和可恢复窗口。
- 审计、账务流水、支付记录、申诉证据和法定保留数据不沿用普通图片清理周期；存在申诉、冻结、调查或对象引用时禁止物理删除。

## 4. 数据与状态要求

管理端展示的所有业务状态必须来自 API。状态变更必须具有操作者、时间、原因和前后值；需要异步处理的动作返回任务 ID 或事件流。

审核状态至少区分 `PENDING`、`AUTO_APPROVED`、`AUTO_REJECTED`、`REVIEW_REQUIRED`、`MANUAL_APPROVED`、`MANUAL_REJECTED`、`APPEALED` 和 `CLOSED`。生成任务的技术状态与内容审核状态分开，不能用“任务成功”推断“内容可公开”。

模型发布、权限变更、额度调整和资产下架必须幂等；重复请求不能创建第二条发布记录、第二次结算或第二次通知。

## 5. 验收门禁

- 桌面 1280px、窄桌面 902px 和移动 390px 无导航覆盖、横向溢出或不可操作按钮。
- 每个写操作至少有 API 单测、权限测试、错误/加载/空状态和一条真实浏览器路径。
- Viewer、Support、Moderator、Model Operator 和 Owner 的越权路径均返回正确的 401/403。
- 人工审核从领取到决定、申诉到复审、下架到恢复均能在数据库和审计中还原。
- 模型草稿发布、健康检查、路由灰度、回滚和供应商失败均有可重复 smoke。
- 用户任务、审核、结果、下载、额度和通知状态在管理端与用户端一致。
- 套餐购买快照、订单入账、任务预扣/结算、退款和人工调整后的额度流水守恒。
- 定时清理在 dry-run、并发执行、失败重跑和引用保护场景下不误删资产，且运行记录可审计。
- 不提交真实手机号、图片、供应商密钥、审核原文或生产数据。

## 6. 实施顺序

1. `ADM-0` 管理端壳、通用状态和服务端授权校验基础设施，不宣称交付权限管理业务。
2. `ADM-1A` 管理员/工号账号、状态、邀请激活、角色分配和会话安全。
3. `ADM-1B` 角色、权限点、角色-权限和账号-角色管理，以及权限矩阵。
4. `ADM-1C` 安全事件与审计日志、撤销和高风险操作保护。
5. `ADM-2A` 用户生命周期、余额/额度流水、套餐权益和订单查询。
6. `ADM-2B` 工作台、任务、灵感和图片资产基础业务管理。
7. `ADM-3` 提示词/图片自动审核、人工队列、下架恢复和申诉。
8. `ADM-4` 模型、供应商、路由、参数、能力和成本管理。
9. `ADM-5` 风控配置、系统配置、定时任务、数据生命周期、隐私请求和指标告警。
10. `ADM-6` 支付退款、额度对账与备份恢复运营增强；对账交互优先级较低，但账务与恢复安全要求不降低。

每个切片完成后先自测，再通知验收，验收通过后才能提交 PR；未完成项不得在阶段计划中标记为完成。
