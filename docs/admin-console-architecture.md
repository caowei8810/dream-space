# 管理端功能架构

本文档把原始产品诉求转换为可开发、可验收的管理端信息架构。管理端服务于内容运营、审核人员、模型运营、客服和系统管理员，不复用普通用户端页面，也不允许浏览器直接访问数据库、对象存储或模型供应商。

## 1. 建设目标

管理端的核心目标是让运营人员可以安全地回答四类问题：

1. 现在平台运行是否正常，用户生成是否成功，额度和成本是否异常？
2. 哪些灵感、上传图片和生成结果可以展示，哪些需要人工复核、下架或申诉？
3. 当前启用了哪些模型、供应商和价格，如何灰度、降级和回滚？
4. 谁在什么时候对用户、内容、模型和系统配置做了什么高风险操作？

额度对账属于运营治理下的 P2 工具。它保留 API、定时任务和详情入口，但不放在一级导航和首页主指标中；只有余额差异、退款异常或账务审计时进入。

## 3. 页面与功能要求

### 3.1 工作台

首屏展示最近 24 小时和当前窗口的可操作指标：任务接受量、成功率、失败率、队列积压、审核待处理数、供应商错误、对象存储错误和异常成本。每个指标必须能跳转到带好筛选条件的真实列表。

异常卡片只展示需要行动的事项；额度对账仅在存在 `BLOCKED` 差异时作为告警入口，不在正常状态占用视觉空间。

### 3.2 内容中心

- 用户生成精选：从用户生成结果中筛选效果好的图片，查看原任务和审核结果，补充标题/分类/排序/展示说明后发布、下架或恢复；不提供独立新建灵感入口。
- 用户上传：归属用户、文件类型、尺寸、审核状态、引用任务、删除/隔离和下载权限。
- 生成作品：按任务、用户、模型、审核状态和时间查看原图/缩略图，支持下架和重新审核。
- 举报与下架：举报来源、理由、证据、处理人、处理结论、通知用户和恢复记录。

### 3.2.1 用户、余额与商业化

用户管理是用户生命周期和商业权益的运营入口，而不是孤立的 CRUD：

- 用户：注册来源、状态、风险标记、会话、任务、审核记录、隐私请求和客服备注；手机号、提示词和原图按角色脱敏。
- 余额与额度：展示可用余额、冻结中额度、已消耗额度、赠送/购买来源和不可变流水；人工调整必须填写原因、幂等键，并支持审批和撤销，不允许直接改余额字段。
- 套餐与权益：套餐编码、名称、价格、额度、有效期、并发/分辨率/模型权益、上下架和版本；已购买用户使用权益快照，套餐变更不影响历史订单或任务。
- 订单与退款：订单、支付渠道、支付状态、退款状态、支付回调和对账引用；管理端不保存银行卡等支付敏感信息，退款和补偿走 API 状态机。
- 用户详情必须能从用户 -> 套餐/订单 -> 额度流水 -> 任务/资产 -> 审核记录串联跳转。

余额账户和套餐权益账户是账务事实，任务和页面统计只是消费证据；任何补偿、退款、赠送和扣减都必须生成可追踪流水。套餐管理只能创建权益和订单，不能自行实现扣减，所有任务统一调用 Billing 引擎。

### 3.2.2 计费引擎

```text
任务提交
  -> 固化模型/活动/套餐规则版本
  -> 幂等检查
  -> 原子预扣：套餐权益优先，否则扣现金余额
  -> 预扣成功才入队
  -> 成功：结算为消费
  -> 失败/取消/拒绝：释放预扣
```

标准批价为每张 `0.10 元`。活动可以配置五折等折扣，但最终价格必须由服务端规则引擎计算并写入任务快照。并发扣款以数据库事务和条件更新为准，禁止出现负余额、负套餐额度或同一幂等请求重复扣款。

所有内容写操作必须记录前后状态和理由；下架是可恢复状态变更，不能直接删除原始审计证据。

### 3.3 审核中心

审核对象包括提示词、参考图、生成原图、缩略图和公开灵感。自动审核与人工审核是两条互补链路：

```text
提交/生成
  -> 自动审核（mock/live）
  -> 通过：按策略公开或交付
  -> 可疑：进入人工队列
  -> 拒绝：隔离资产、释放或结算任务、通知用户
人工复核
  -> 通过 / 拒绝 / 升级 / 申请补充证据
申诉
  -> 初审 -> 复审 -> 最终结论
```

审核规则必须覆盖文生图提示词、参考图、生成结果和公开灵感，至少支持涉黄、涉敏、暴恐、违法、未成年人、版权/肖像和垃圾滥用等风险分类。规则配置与审核结果分离：规则改动版本化，历史案例保留当时的规则版本、引擎、风险码和置信度。审核服务不可用时按配置进入隔离或人工队列，不能默许发布。

审核列表支持优先级、风险码、来源、模型、时间、语言和状态筛选；详情必须显示原始输入、自动审核版本与结果、风险码、人工意见、历史操作和关联任务。人工审核采用“领取-处理-提交”状态，防止多人同时处理；高风险解封或规则变更支持双人审批。

### 3.4 生成运营

- 任务监控：状态、用户、会话、模型、参数、审核状态、耗时、重试和结果资产。
- 失败与死信：错误分类、供应商错误码、尝试次数、重新入队和人工关闭。
- 队列与供应商健康：队列深度、处理速率、超时、限流、熔断和当前路由。
- 结果资产：原图/缩略图、对象键、校验和、审核状态、访问次数和生命周期。

任何“重试、取消、重新审核、下架、重放回调”按钮都必须调用 API，并在成功后刷新服务端状态；不可对页面状态做假修改。

### 3.5 模型中心

- 模型目录：展示名、模型 ID、能力、比例/分辨率/张数限制、版本、状态和默认参数。
- 供应商连接：凭据引用、健康检查、超时、限流、回调验签状态和最近错误；前端不展示 Secret。
- 路由与灰度：按模型、用户分组、流量比例、地域和故障降级配置，发布前预览影响范围。
- 参数模板：用户端可见选项与供应商参数的映射、默认值、校验和版本。
- 成本与额度：单张成本、倍率、免费额度规则和生效时间；变更需审批并留下审计记录。

模型运营必须同时管理“能力配置”和“商业计费配置”：模型能力决定前台可选项，价格/倍率决定额度预扣，二者都以版本快照写入任务，确保后续追溯。

模型配置采用草稿 -> 校验 -> 审批 -> 发布 -> 回滚生命周期，禁止直接修改线上生效值。

### 3.6 用户与权限

用户管理支持搜索、状态、注册时间、生成统计、额度、审核记录、风险标记、会话和隐私请求；客服可查看必要信息，但默认隐藏手机号、提示词和原图等敏感内容。

管理员角色建议如下：

| 角色             | 核心权限                     | 禁止事项                     |
| ---------------- | ---------------------------- | ---------------------------- |
| Owner            | 全部配置、账号、权限和审计   | 仍需遵守双人审批规则         |
| Admin            | 内容、任务、用户和运营配置   | 不能管理 Owner 和密钥        |
| Content Operator | 灵感、公开作品、排序和来源   | 不能改模型、额度和权限       |
| Moderator        | 自动/人工审核、申诉、下架    | 不能改审核规则和供应商       |
| Model Operator   | 模型、供应商、路由和成本草稿 | 不能直接审批自己的发布       |
| Support          | 用户查询、任务协助和申诉查看 | 默认不可下载原图、不可写配置 |
| Viewer           | 只读指标、任务和内容         | 不显示任何写操作             |

权限采用 `resource:action` 形式，例如 `models:publish`、`moderation:decide`、`users:quota-adjust`。高风险权限单独标记，支持临时授权、过期时间和审批人。

### 3.7 系统运营

- 系统配置：功能开关、外围 `mock/live`、上传限制、任务并发、审核阈值和维护模式。
- 风控配置：提示词黑白名单、正则/分类器阈值、用户/设备/IP 频控、重复内容拦截、人工审核抽检比例和规则灰度；配置采用草稿、校验、审批、发布、回滚生命周期。
- 定时任务与数据生命周期：任务定义、Cron、启停、最近运行、下次运行、租约、失败重试和运行日志；覆盖过期任务、临时文件、生成图片、参考图、会话事件和审计索引的分层清理。删除前必须经过保留期校验、软删除/隔离和可恢复窗口，禁止用一次性脚本直接删生产数据。
- 审计日志：操作者、角色、请求 ID、IP、对象、前值、后值、理由、审批链和时间。
- 指标与告警：链接到可观测平台，不在管理端复制一套统计真相。
- 数据留存与隐私请求：导出、删除、匿名化、保留期限和任务状态影响评估。
- 额度对账（P2）：运行记录、差异、补偿和 `BLOCKED` 项；仅允许安全补偿或转人工处置。

## 4. API 与数据边界

管理端页面只调用 API，推荐模块边界如下：

| 模块            | 主要接口                                                                                                      | 核心实体                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Dashboard       | `GET /admin/dashboard/summary`                                                                                | 指标快照、异常摘要                                                       |
| Content         | `GET /admin/inspirations`、`POST /admin/inspirations/:id/publish`、`POST /admin/inspirations/:id/unpublish`   | UserGeneratedAsset、InspirationCuration、Report                          |
| Users/Billing   | `GET /admin/users`、`GET /admin/users/:id/quota-ledger`、`GET/POST /admin/plans/*`                            | User、QuotaAccount、QuotaLedger、Plan、Order、Refund                     |
| Billing         | `GET/POST/PATCH /admin/billing/rules/*`、`GET /admin/billing/ledger`、`GET /admin/billing/settlements`        | BillingRule、Campaign、PriceSnapshot、Charge、Settlement                 |
| Moderation      | `GET /admin/moderation/queue`、`POST /admin/moderation/:id/decision`                                          | ModerationCase、Decision、Appeal                                         |
| Generation      | `GET /admin/tasks`、`GET /admin/tasks/:id`、`POST /admin/tasks/:id/retry`                                     | GenerationTask、Event、DeadLetter                                        |
| Models          | `GET/POST/PATCH /admin/models/*`、`POST /admin/models/:id/publish`                                            | Model、Provider、Route、PriceRule                                        |
| Identity/Access | `GET/POST/PATCH /admin/admin-users/*`、`GET/POST/PATCH /admin/roles/*`、`GET/POST/PATCH /admin/permissions/*` | AdminUser、Role、Permission、RolePermission、AdminUserRole、AdminSession |
| Risk/Config     | `GET/POST /admin/risk-rules/*`、`GET/POST /admin/configs/*`                                                   | RiskRule、RuleVersion、SystemConfig                                      |
| Operations      | `GET /admin/audit-logs`、`GET/POST /admin/scheduled-jobs/*`、`GET /admin/quota-reconciliation/*`              | AuditLog、ScheduledJob、JobRun、ReconciliationRun                        |

接口统一使用分页、筛选 DTO、排序白名单、请求 ID 和权限守卫；写接口返回服务端最终状态。数据库迁移按领域拆分，管理端不能绕过 API 直接调用 Prisma。

### 4.1 领域边界与数据归属

管理端按业务能力划分模块，模块之间通过 API/应用服务和领域事件协作，不共享可变表写权限：

| 领域             | 负责的事实                       | 允许写入                          | 禁止承担                             |
| ---------------- | -------------------------------- | --------------------------------- | ------------------------------------ |
| Identity/Access  | 管理员、角色、权限、会话、授权   | 账号状态、角色绑定、授权记录      | 直接修改业务对象或自授高危权限       |
| Content          | 用户生成资产精选、举报           | 精选元数据、可见性、隔离/恢复标记 | 创建无用户生成来源的灵感或绕过审核   |
| Moderation       | 审核案例、规则版本、决定、申诉   | 审核决定、证据、通知指令          | 修改任务技术状态或额度流水           |
| Generation Ops   | 任务、事件、重试、死信、队列     | 运维动作和处置备注                | 伪造任务成功或结果资产               |
| Model Ops        | 模型、供应商、路由、参数、成本   | 草稿、发布记录、健康检查          | 在前端暴露密钥或跳过审批改线上值     |
| Operations       | 配置、审计、指标入口、隐私请求   | 配置版本、审计索引、请求状态      | 复制监控真相或删除原始审计           |
| Quota/Accounting | 额度流水、对账、补偿             | 幂等流水和阻塞处置                | 根据页面统计猜测余额                 |
| Commerce         | 套餐、权益快照、订单、退款       | 套餐版本和订单状态迁移            | 直接修改额度余额或保存支付敏感信息   |
| Billing          | 标准价、活动价、预扣、结算和退款 | 计费规则版本、扣款流水、结算记录  | 绕过账本直接修改余额或由前端计算价格 |
| Risk Control     | 风控规则版本、命中记录、处置     | 规则草稿/发布和风险标记           | 覆盖人工审核结论或静默放行           |

跨域写操作必须由 API 编排事务或可靠事件完成。例如下架生成结果由 Moderation 产生决定，Content 更新可见性，Generation Ops 处理交付权限，Quota 依据已有流水结算；任何一步失败都要可重试、可追踪，不能只更新管理端页面。

### 4.2 关键状态约束

```text
权限：INVITED -> ACTIVE -> SUSPENDED -> REVOKED
审核：PENDING -> AUTO_APPROVED | AUTO_REJECTED | REVIEW_REQUIRED
人工审核：REVIEW_REQUIRED -> MANUAL_APPROVED | MANUAL_REJECTED | ESCALATED
申诉：SUBMITTED -> IN_REVIEW -> SECOND_REVIEW -> APPROVED | REJECTED -> CLOSED
模型发布：DRAFT -> VALIDATED -> PENDING_APPROVAL -> PUBLISHED -> ROLLED_BACK
```

状态迁移只能由服务端根据当前版本执行，重复请求返回最终状态（幂等），非法迁移返回明确错误。高风险迁移（解封、模型发布、权限升级、额度处置、隐私删除）必须满足操作者与审批者分离、原因必填和审计完整；自动审核异常默认进入人工或隔离，不得静默放行。

## 5. 分阶段实施路线

| 切片   | 目标                                               | 优先级 | 验收证据                                              |
| ------ | -------------------------------------------------- | ------ | ----------------------------------------------------- |
| ADM-0  | 管理端壳、统一状态和服务端授权校验基础设施         | P0     | 桌面/移动布局、路由守卫、无权限 403 E2E               |
| ADM-1A | 基础管理：管理员工号、账号状态、角色分配和会话安全 | P0     | 账号生命周期 API、最后 Owner 保护、撤销会话测试       |
| ADM-1B | 权限管理：角色、权限点及两类关联关系               | P0     | 角色矩阵 API、越权与自授权阻断测试                    |
| ADM-1C | 安全事件与审计日志                                 | P0     | 高风险操作审计查询和不可抵赖性测试                    |
| ADM-2A | 用户生命周期、余额账户、额度流水和订单查询         | P0     | 注册用户可见、封禁/限制生效、账本守恒和权限测试       |

## 6. 当前差距

已完成的历史能力：独立管理员登录、RBAC 基础守卫、旧灵感 CRUD/发布下架、任务查询/详情、Viewer 只读态、额度对账接口展示，以及用户生命周期管控（注册用户可见、限制生成、封禁/解封、会话撤销和服务端拦截）。旧灵感新建能力将在 P2-7 移除并改为用户生成结果精选。

缺失且按 ADM-1B 至 ADM-6 推进：动态角色/权限点及关联管理、完整审计查询、工作台、用户余额不可变流水、套餐/权益/订单/退款、完整人工审核工作台、审核申诉、模型目录/供应商/路由/成本配置、提示词风控规则、系统配置、定时任务与数据生命周期 API/数据库实体。

因此当前管理端仍是“内容和任务切片”，不能宣称为完整运营后台；阶段 B5 只代表 MVP 管理端完成，不代表商用管理端完成。
