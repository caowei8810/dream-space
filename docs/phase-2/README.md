# 造梦空间 Phase 2 交付物

Phase 2 的目标是把 Phase 1 已验证的用户端图片生成体验扩展为可运营、可计费、可审核、可配置的商用平台。Phase 1 的用户端视觉和核心交互继续以 `prototype/index.html` 与 `docs/phase-1/` 为基线；Phase 2 只定义增量功能和管理后台，不反向改写 Phase 1 的历史结论。

## 来源优先级

发生冲突时按以下顺序处理：

1. 产品负责人最新明确确认并已回写的决策。
2. 本目录的 Phase 2 正式需求。
3. `docs/phase-1/` 与 `prototype/index.html` 的用户端基线。
4. 架构、开发计划和商用就绪文档。
5. 当前代码实现。

代码不是产品需求的事实来源。确认后的需求与代码冲突时，应修改代码并补充迁移、测试和回滚方案。

## 执行纪律

每个阶段均执行：设计与目标确认 -> 实现 -> 单元测试 -> API smoke -> 服务启动 -> 自测 -> 用户验收 -> 提交 PR。未自测不得通知验收，未验收不得提交 PR，未明确批准不得合并。
