# Repository Workflow

- Treat `main` as protected. Do not commit or push feature work directly to `main`.
- Create a focused `feature/`, `fix/`, `design/`, `docs/`, or `chore/` branch for every change.
- Use concise commits that state the actual modification.
- Push the branch and create a pull request for user review.
- Do not merge a pull request without explicit user approval.
- Keep credentials and user data out of files, commits, logs, issues, and pull requests.
- For prototype changes, run JavaScript syntax, duplicate-ID, missing-DOM-target, theme, localization, and responsive-layout checks appropriate to the change.
